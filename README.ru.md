# clipweb

[English version](README.md)

`clipweb` извлекает эпизоды с веб-камеры из записей стримов. По умолчанию программа определяет одну небольшую вебку рядом с углом кадра, фиксирует этот прямоугольник на весь стрим, исключает участки без обнаруженного лица, размывает вебку во время вероятного курения и сохраняет каждый оставшийся эпизод отдельным MP4. По умолчанию речь и прочие звуки не влияют на отбор.

## Требования и запуск

Установите Python 3.11 или новее, [uv](https://docs.astral.sh/uv/) и FFmpeg так, чтобы команда `ffmpeg` была доступна в `PATH`. В Windows совместимая видеокарта и драйвер позволяют ускорить модель курения через DirectML.

```text
uv sync
uv run clipweb
```

Положите записи в `input/`. Папки `input/`, `output/` и `logs/` создаются автоматически. Файл `config.yaml` с настройками по умолчанию хранится в репозитории и остаётся после `git clean -ffdx`; при ручном удалении программа его не восстанавливает. Команда `git clean -ffdx` удаляет игнорируемые файлы, включая записи, результаты, кэш, журналы и `.venv`. Вместо этого в `paths.source` файла `config.yaml` можно указать один файл или папку — абсолютным путём или относительно `config.yaml`. Все настройки находятся в этом файле; запускайте команду из папки проекта. Поддерживаются MP4, MKV, MOV, AVI, WebM и M4V.

## Независимые модули обработки

При `webcam.auto: true` программа берёт `webcam.samples` кадров из разных частей записи и ищет повторяющееся лицо в небольшой области около угла. Затем оценивает один прямоугольник вебки и фиксирует его на всю запись: не двигает и не масштабирует. Найденные `x`, `y`, `width`, `height` выводятся в лог в пикселях исходного кадра. Затем `aspect.enabled: true` и `aspect.ratio: "16:10"` выбирают внутри вебки максимальный прямоугольник с указанными пропорциями по центру, без растягивания и масштабирования; итоговая неподвижная область также записывается в лог. Формат `aspect.ratio` можно изменить, например на `9:16`; `aspect.enabled: false` сохраняет исходные размеры вебки. Одна и та же итоговая область используется для проверки лица, курения и сохранения видео. Если устойчивое положение не найдено, программа завершит обработку с ошибкой. Для ручного выбора установите `webcam.auto: false` и задайте четыре координаты.

Лицо проверяется с частотой `analysis.sample_fps` (по умолчанию 5 кадров в секунду), поэтому границы отбора определяются по этой сетке, а не с точностью до отдельного кадра. При `face.enabled: true` участки без обнаруженного лица исключаются; `face.missing_tolerance_seconds` по умолчанию объединяет пропуски до 5 секунд, ограниченные с обеих сторон обнаруженным лицом; такие секунды сохраняются даже при кратковременном уходе человека. Если выключить `face.enabled`, такие участки останутся. При длительном отсутствии лица или перемещении камеры могут возникать ошибки. Детектор лица OpenCV использует эвристику: поворот головы, перекрытие, маленькое лицо или другое лицо внутри фиксированной области могут привести к ошибкам. Камера при изменении положения или масштаба не отслеживается. Для записей с другим оформлением проверяйте найденную область и примеры результатов.

Детектор курения включён по умолчанию. Он проверяет фиксированную область вебки в интервалах, оставленных включёнными фильтрами лица и речи, и обрабатывает вероятные эпизоды курения вместе с настроенным запасом. По умолчанию `smoking.blur: true` сохраняет эти моменты и размывает только область обнаруженного объекта; сила задаётся через `smoking.blur_sigma`. При `smoking.blur_near_mouth: true` объекты далеко от рта найденного лица отклоняются. `smoking.blur_margin_pixels` расширяет рамку, а `smoking.blur_hold_seconds` ограничивает время действия каждой находки. Чтобы вместо этого вырезать найденные эпизоды, задайте `smoking.blur: false`. Звук остаётся без изменений, если отдельно не включён `mute.enabled`. Размытие действует только рядом с кадрами, где найден объект, и не гарантирует, что всё курение будет скрыто: сигарета может остаться видимой между проверками, при потере лица или в отведённой руке. Если в событии не найдено подходящей рамки, оно не размывается, и об этом пишется предупреждение в лог. Это экспериментальная модель: рука или предмет могут дать ложное обнаружение, а сигарета может быть пропущена. Точность и число ложных срабатываний регулируются `smoking.confidence`, `min_hits`, `max_gap_seconds`, запасами времени и частотой выборки. `smoking.backend: auto` использует ONNX Runtime DirectML при доступности и иначе OpenCV на CPU; `directml` требует DirectML, `cpu` принудительно выбирает CPU. `device_id` — индекс адаптера DXGI; после изменения оборудования он может поменяться. Часть операций модели может выполняться на CPU. Авторство и лицензия модели находятся в `models/`.

При `output.split_episodes: true` результат сохраняется в `output/<имя-исходного-файла-без-расширения>/`. Имя каждого MP4 — `<первый>-<последний>.mp4`: это **номера декодированных кадров исходной записи, начиная с нуля, включая оба указанных кадра**. Программа считает настоящие кадры по временным меткам, а не умножает время на номинальный FPS. Интервалы по времени включают начало и исключают конец, поэтому последний номер относится к последнему кадру до конца интервала. Если в исходнике есть аудио, в каждом эпизоде сохраняется соответствующий звук; `mute.enabled: true` убирает аудиодорожку из экспортируемых файлов. Кодек и качество задаются в `output`.

`output.min_segment_seconds` удаляет слишком короткие фрагменты после обработки курения; по умолчанию это `60`: фрагменты короче одной минуты не рендерятся. Установите `0`, чтобы сохранить все непустые интервалы. Короткие пропуски лица объединяются только в пределах указанного допуска; в режиме вырезания интервалы курения обратно не соединяются.

Результаты анализа сохраняются в `output/.clipweb_cache/`. Размер и время изменения исходника, выбранная область и настройки детектирования участвуют в проверке кэша. При выключенном фильтре речи подходящий кэш анализа лица с нулевым допуском используется повторно при изменении допуска, без повторного чтения видео. Анализ курения выполняется заново, поскольку прежний кэш не охватывает добавленные промежутки. При изменении режима или силы размытия кэш поиска курения используется повторно; повторный запуск пересобирает результаты. Для принудительного пересчёта задайте `processing.reanalyze: true`. Список сгенерированных файлов позволяет при повторном запуске заменить управляемые эпизоды и после успешной сборки убрать устаревшие, не затрагивая посторонние файлы. При совпадении имени с чужим файлом программа остановится. Не удаляйте кэш, если нужна автоматическая замена существующего набора; если кэш потерян, перед повторным запуском переместите старую папку результата.

## Сочетание модулей

Каждый переключатель работает независимо: `webcam.enabled` включает обрезку вебки (`false` использует весь кадр исходника), `webcam.auto` выбирает автоматические или ручные координаты при включённой обрезке; `face.enabled` удаляет участки без лица; `speech.enabled` включает фильтр речи; `smoking.enabled` включает фильтр курения; `aspect.enabled` включает обрезку под формат; `mute.enabled` сохраняет видео без аудиодорожки; `output.split_episodes` выбирает отдельные файлы (`true`) или один склеенный `output/<имя>_clipweb.mp4` (`false`). Например, можно выключить фильтр лица и оставить фильтр курения либо включить фильтр речи и сохранять отдельные эпизоды.

Отключение звука влияет только на экспорт: включённый фильтр речи по-прежнему анализирует аудио исходника. Когда фильтр речи включён, `speech.method` выбирает `both` (голос и движение рта), `speech` (только голос) или `mouth` (только движение рта). `speech.invert: true` оставляет речь вместо удаления. Методы, использующие рот, определяют лицо для поиска рта даже при `face.enabled: false`, но отсутствие лица не вырезается, пока фильтр лица выключен. Автопоиск вебки также использует лицо для определения положения камеры. Если обрезка вебки выключена, включённая обрезка формата применяется ко всему исходному кадру; нечётные размеры исходника округляются вниз до чётных пикселей для кодирования. Эти эвристики не распознают личность: чужая речь, еда, движение головы и открытый рот могут классифицироваться ошибочно. `output.join_gap_seconds` объединяет интервалы до обработки курения и может вернуть материал, удалённый фильтрами лица или речи; по умолчанию задано `0`.

## Прогресс и журналы

Консоль показывает общий прогресс, прогресс файла и отдельных этапов. Общий процент назначает этапам равные веса. `ETA ~` — приблизительная оценка по измеренной скорости: аудио и видео анализируются параллельно, поиск курения и сборка выполняются последовательно. До начала следующих этапов их длительность оценивается по более медленному этапу анализа, а остальные файлы считаются похожими на текущий. Оценка может значительно измениться. `source` показывает позицию в исходной записи, а не время обработки.

`logging.console_level` и `logging.file_level` независимо задают уровни вывода в консоль и файл. Для каждого запуска создаётся отдельный журнал UTF-8 в `logs/`, у сообщений есть идентификаторы фиксированной ширины. Внешние файлы настроек для журналов не нужны.

## Проверка и ограничения

Тесты запускаются командой `uv run python -m unittest discover -s tests`. Для измерения и проверки минимального покрытия 95% выполните `uv run python -m coverage run --source=clipweb -m unittest discover -s tests`, затем `uv run python -m coverage report`. Проверки, которым нужен FFmpeg, пропускаются, если он не установлен. Результат зависит от исходника, расположения вебки, кодека и модели; проверяйте характерные эпизоды перед важной обработкой. Несколько лиц или сильная смена оформления могут ошибочно повлиять на автоматический выбор. Кадры без временных меток или с убывающими временными метками не позволяют надёжно определить номера — программа выдаёт ошибку вместо предположения. Номера в именах относятся к видеокадрам, а не к отсчётам аудио.

Кэш старого анализа интервалов курения используется повторно: если координат объектов в нём ещё нет, программа дополнительно проверит только сохранённые интервалы курения. Координаты хранятся отдельно; изменение `blur_near_mouth` запускает их повторный поиск.

Если Windows временно отказывает FFmpeg в доступе к временному файлу эпизода, программа до трёх раз повторяет попытку с новым временным файлом. Постоянная ошибка доступа записывается в лог, эпизод не считается успешно сохранённым.

## Запуск из workflow

Из папки проекта:

```powershell
uv run clipweb --config D:/jobs/job-42.yaml --source D:/media/movie.mp4
```

Используйте [config.example.yaml](config.example.yaml) как шаблон. В YAML задаются все настройки
обработки и выходная папка. Относительные пути в YAML отсчитываются от
папки конфигурации.
Пути в аргументах CLI отсчитываются от рабочей папки процесса.
Без `--source` используется обычный выбор входных файлов из конфигурации.
Код 0 означает успешное завершение. Перед следующим этапом проверьте наличие
ожидаемого результата. Формат выходных путей описан в [README.md](README.md).

В Python передавайте аргументы списком в `subprocess.run` с `cwd`, равным
папке проекта, и `check=True`. Независимые задачи можно запускать отдельными
процессами. Если выходные пути могут совпасть, задавайте разные выходные папки.
Следующий этап для конкретного файла запускайте после завершения предыдущего.
