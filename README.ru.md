# clipweb

[English version](README.md)

`clipweb` извлекает эпизоды с веб-камеры из записей стримов. В основном режиме программа определяет одну небольшую вебку рядом с углом кадра, фиксирует этот прямоугольник на весь стрим, исключает участки без обнаруженного лица и вероятные эпизоды курения, а каждый оставшийся эпизод сохраняет отдельным MP4. Речь и прочие звуки в этом режиме не влияют на отбор.

## Требования и запуск

Установите Python 3.11 или новее, [uv](https://docs.astral.sh/uv/) и FFmpeg так, чтобы команда `ffmpeg` была доступна в `PATH`. В Windows совместимая видеокарта и драйвер позволяют ускорить модель курения через DirectML.

```text
uv sync
uv run clipweb
```

Положите записи в `input/`. Папки `input/`, `output/` и `logs/` создаются автоматически. Вместо этого в `paths.source` файла `config.yaml` можно указать один файл или папку — абсолютным путём или относительно `config.yaml`. Все настройки находятся в этом файле; запускайте команду из папки проекта. Поддерживаются MP4, MKV, MOV, AVI, WebM и M4V.

## Основной режим: отдельные эпизоды

По умолчанию задано `processing.mode: episodes`. Программа берёт `webcam.samples` кадров из разных частей записи и ищет повторяющееся лицо в небольшой области около угла. Затем оценивает один прямоугольник вебки и фиксирует его на всю запись: не двигает и не масштабирует. Найденные `x`, `y`, `width`, `height` выводятся в лог в пикселях исходного кадра. Затем `output.aspect_ratio: "16:10"` выбирает внутри вебки максимальный прямоугольник с указанными пропорциями по центру, без растягивания и масштабирования; итоговая неподвижная область также записывается в лог. Формат можно изменить, например на `9:16`, или задать `source`, чтобы оставить исходные размеры вебки. Одна и та же итоговая область используется для проверки лица, курения и сохранения видео. Если устойчивое положение не найдено, программа завершит обработку с ошибкой. Для ручного выбора установите `webcam.auto: false` и задайте четыре координаты.

Лицо проверяется с частотой `analysis.sample_fps` (по умолчанию 5 кадров в секунду), поэтому границы отбора определяются по этой сетке, а не с точностью до отдельного кадра. Участки без обнаруженного лица исключаются; `processing.face_missing_tolerance_seconds` допускает короткие пропуски детектора. При длительном отсутствии лица или перемещении камеры могут возникать ошибки. Детектор лица OpenCV использует эвристику: поворот головы, перекрытие, маленькое лицо или другое лицо внутри фиксированной области могут привести к ошибкам. Камера при изменении положения или масштаба не отслеживается. Для записей с другим оформлением проверяйте найденную область и примеры результатов.

Детектор курения включён по умолчанию. Он проверяет фиксированную область вебки только в интервалах с лицом и вырезает вероятные эпизоды курения вместе с настроенным запасом. Это экспериментальная модель: рука или предмет могут дать ложное обнаружение, а сигарета может быть пропущена. Точность и число ложных срабатываний регулируются `smoking.confidence`, `min_hits`, `max_gap_seconds`, запасами времени и частотой выборки. `smoking.backend: auto` использует ONNX Runtime DirectML при доступности и иначе OpenCV на CPU; `directml` требует DirectML, `cpu` принудительно выбирает CPU. `device_id` — индекс адаптера DXGI; после изменения оборудования он может поменяться. Часть операций модели может выполняться на CPU. Авторство и лицензия модели находятся в `models/`.

Результат сохраняется в `output/<имя-исходного-файла-без-расширения>/`. Имя каждого MP4 — `<первый>-<последний>.mp4`: это **номера декодированных кадров исходной записи, начиная с нуля, включая оба указанных кадра**. Программа считает настоящие кадры по временным меткам, а не умножает время на номинальный FPS. Интервалы по времени включают начало и исключают конец, поэтому последний номер относится к последнему кадру до конца интервала. Если в исходнике есть аудио, в каждом эпизоде сохраняется соответствующий звук. Кодек и качество задаются в `output`.

`processing.min_segment_seconds` удаляет слишком короткие фрагменты после фильтра курения; по умолчанию это `0`, то есть сохраняются все непустые эпизоды. Для старого режима используется отдельная настройка `output.min_segment_seconds` (по умолчанию `0.5` секунды). Короткие пропуски лица объединяются только в пределах указанного допуска; интервалы, вырезанные из-за курения, обратно не соединяются.

Результаты анализа сохраняются в `output/.clipweb_cache/`. Размер и время изменения исходника, выбранная область и настройки участвуют в проверке кэша. Для принудительного пересчёта задайте `processing.reanalyze: true`. Список сгенерированных файлов позволяет при повторном запуске заменить управляемые эпизоды и после успешной сборки убрать устаревшие, не затрагивая посторонние файлы. При совпадении имени с чужим файлом программа остановится. Не удаляйте кэш, если нужна автоматическая замена существующего набора; если кэш потерян, перед повторным запуском переместите старую папку результата.

## Старый режим

Для прежнего варианта задайте `processing.mode: legacy`. Он использует заданные `webcam.x/y/width/height` без автоматического поиска и обрезки формата из режима эпизодов, применяет `analysis.speech_detection` и `analysis.invert_speech`, объединяет соседние интервалы через `output.join_gap_seconds`, при включённом фильтре убирает курение и сохраняет один файл `output/<имя>_clipweb.mp4`. `both` учитывает голос и движение рта, `speech` — голос, `mouth` — движение рта, `face` — только лицо. Это эвристики, а не распознавание личности: чужую речь, еду, движения головы и открытый рот они могут классифицировать ошибочно.

## Прогресс и журналы

Консоль показывает общий прогресс, прогресс файла и отдельных этапов. Общий процент назначает этапам равные веса. `ETA ~` — приблизительная оценка по измеренной скорости: аудио и видео анализируются параллельно, поиск курения и сборка выполняются последовательно. До начала следующих этапов их длительность оценивается по более медленному этапу анализа, а остальные файлы считаются похожими на текущий. Оценка может значительно измениться. `source` показывает позицию в исходной записи, а не время обработки.

`logging.console_level` и `logging.file_level` независимо задают уровни вывода в консоль и файл. Для каждого запуска создаётся отдельный журнал UTF-8 в `logs/`, у сообщений есть идентификаторы фиксированной ширины. Внешние файлы настроек для журналов не нужны.

## Проверка и ограничения

Тесты запускаются командой `uv run python -m unittest discover -s tests`. Для измерения и проверки минимального покрытия 95% выполните `uv run python -m coverage run --source=clipweb -m unittest discover -s tests`, затем `uv run python -m coverage report`. Проверки, которым нужен FFmpeg, пропускаются, если он не установлен. Результат зависит от исходника, расположения вебки, кодека и модели; проверяйте характерные эпизоды перед важной обработкой. Несколько лиц или сильная смена оформления могут ошибочно повлиять на автоматический выбор. Кадры без временных меток или с убывающими временными метками не позволяют надёжно определить номера — программа выдаёт ошибку вместо предположения. Номера в именах относятся к видеокадрам, а не к отсчётам аудио.
